# Results

`colorings.csv` has one row per (graph, algorithm). It is generated by `python -m utils.bench`, run
from the repo root. Two runs make up the current file:

- `python -m utils.bench --state WA CA TX` covers the 24 WA/CA/TX map graphs.
- `python -m utils.bench --state all --layer county --source tiger --mode rook --census` covers
  the 104 county graphs of every state.
- `python -m utils.bench --no-maps --rome 1000 --ba-n 50 100 200 500 1000 2000 --ba-m 3 --ba-seeds 5 --repeats 5 --orders 10`
  covers the Rome and BA graphs. These use 5 timing repeats and 10 relabelings instead of 21 and
  50.

Rerunning replaces the rows for the graphs that were run and keeps all other rows.

| column | meaning |
|--------|---------|
| `graph` | graph id, e.g. `wa_county_tiger_rook` |
| `family` | `map`, `rome` or `ba`. For Rome, `source` names the sample (`rome_sample1000_seed0`); for BA, `source` is `barabasi_albert_m3` and the graph id is `ba_n<n>_m<m>_s<seed>` |
| `state` | state abbreviation (50 states, `DC`, `PR`) |
| `layer`, `source`, `mode`, `min_shared_m`, `snap_m` | how the map was turned into a graph (see the main README). `source=census` is the Census County Adjacency File (always `mode=queen`) |
| `n`, `m` | nodes, edges |
| `algorithm` | `largest_first`, `dsatur`, `smallest_last`, `independent_set`, `exact`, `sat` |
| `colors` | colors used with nodes labeled 0..n-1 in sorted-ID order (reproducible) |
| `chromatic_number` | minimum possible, from `exact`; the run fails unless `sat` gets the same value |
| `gap` | `colors - chromatic_number` |
| `colors_min`, `colors_mean`, `colors_max` | colors used over `orders` seeded random relabelings: how much the result depends on tie-breaking |
| `orders` | number of random relabelings; 0 for `exact` and `sat` (optimal on every labeling; `exact` is too slow on some) |
| `runtime_ms_median`, `runtime_ms_min` | time of the coloring call only, over `repeats` runs |
| `repeats` | timing repeats |
| `run_at` | UTC timestamp of the run |
| `networkx` | networkx version; tie-breaking can change between versions |
| `status` | `ok`, or `timeout` when `exact`/`sat` hit `--exact-time-limit` (then `colors` and runtimes are empty). Empty on rows from before this column existed |

## Other files

- `county_metrics.csv`: one row per county graph (104), written by `python -m utils.graph_metrics`.
  - **Structure:** `n`, `m`, `density`, `components`, `isolated`, `mean_degree`, `max_degree`,
    `degeneracy`, `triangles`, `transitivity`, `avg_clustering`, `omega` (largest clique),
    `maximal_cliques`, `k4_count`, `odd_wheel_hubs`, `planar`.
  - **Coloring:** `chi`; `k_steps` (how many k the exact methods tried; 2 means ω < χ);
    `omega_lt_chi`.
  - **Search effort, on the integer labeling:**
    - `exact_nodes` and `exact_nodes_per_k`: backtracking search-tree nodes, in total and per k
    - `exact_status`, and `exact_ms_once` for a single exact call
    - `sat_conflicts`, `sat_decisions`, and `sat_clauses_final`
  - **Order probe, over `probe_orders` random relabelings with a 2 s limit each:**
    `probe_nodes_median`, `probe_nodes_max`, `probe_ms_median`, `probe_ms_max`, `probe_timeouts`.
  - **Joined from `colorings.csv`:** `ms_<algorithm>` (median runtime) and `gap_<algorithm>`.
- `rome_metrics.csv`, `ba_metrics.csv`: the same columns for the 1000 sampled Rome graphs and the
  30 Barabási–Albert graphs (m = 3, n = 50–2000, seeds 0–4), written by
  `python -m utils.graph_metrics --family rome|ba`. The matching `*_runtime_correlations.csv` files
  hold the correlations. On BA, the degeneracy (3) and ω (4) columns are the same for every graph,
  so their correlation is undefined (NaN).
- `rome_ba_analysis.md`: write-up comparing county maps, Rome and BA graphs, including the
  planarity question.
- `county_runtime_correlations.csv`: Spearman correlation of each algorithm's median runtime with
  each metric (graphs with n ≥ 5).
- `county_analysis.md`: the write-up of what these numbers show.
- `state_summary.csv` / `state_summary.md`: written by `python -m utils.state_summary`. One row
  per state with counties, edges, largest clique, colors needed, and each algorithm's median
  runtime (ms), for both the Census and rook graphs. The `.md` file shows the Census columns as a
  readable table. Charts of the same data: `figures/state_runtime_census.png` and
  `figures/state_runtime_rook.png`.
- `figures/`: plots used in the write-up:
  - `runtime_vs_n.png`
  - `exact_effort.png`
  - `exact_order_sensitivity.png`
  - `heuristic_misses.png`

## Why relabel?

networkx breaks ties for `smallest_last` and `independent_set` by iterating sets. With string node IDs
(GEOIDs), that order depends on Python's per-process hash seed, so the same graph could need 4
colors in one run and 5 in the next. Relabeling to integers makes `colors` reproducible. The
min/mean/max columns report the variation instead of hiding it.

Runtimes are for one machine and are sub-millisecond on map graphs. Compare them within a run, not
across machines.
