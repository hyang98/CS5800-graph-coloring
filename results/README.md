# Results

`colorings.csv` has one row per (graph, algorithm). It is generated by `python bench.py`, run from
the parent folder. Rerunning replaces the rows for the graphs that were run and keeps all other rows.

| column | meaning |
|--------|---------|
| `graph` | graph id, e.g. `wa_county_tiger_rook` |
| `family` | `map` for now; later `rome`, `ba` |
| `layer`, `source`, `mode`, `min_shared_m`, `snap_m` | how the map was turned into a graph (see the main README) |
| `n`, `m` | nodes, edges |
| `algorithm` | `largest_first`, `dsatur`, `smallest_last`, `independent_set`, `exact` |
| `colors` | colors used with nodes labeled 0..n-1 in sorted-ID order (reproducible) |
| `chromatic_number` | minimum possible, from `exact` |
| `gap` | `colors - chromatic_number` |
| `colors_min`, `colors_mean`, `colors_max` | colors used over `orders` seeded random relabelings: how much the result depends on tie-breaking |
| `orders` | number of random relabelings |
| `runtime_ms_median`, `runtime_ms_min` | time of the coloring call only, over `repeats` runs |
| `repeats` | timing repeats |
| `run_at` | UTC timestamp of the run |
| `networkx` | networkx version; tie-breaking can change between versions |

## Why relabel?

networkx breaks ties for `smallest_last` and `independent_set` by iterating sets. With string node IDs
(GEOIDs), that order depends on Python's per-process hash seed, so the same graph could need 4
colors in one run and 5 in the next. Relabeling to integers makes `colors` reproducible. The
min/mean/max columns report the variation instead of hiding it.

Runtimes are for one machine and are sub-millisecond on map graphs. Compare them within a run, not
across machines.
